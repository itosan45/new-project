## きっかけ

「蓋を開けてみたら何も定義されてない、何もわからないエージェントが動いて
意味のわからないものができた、ってならないようにしたい」

そのとおりの状態になっていた。

## 何が起きていたか

`pipeline.ts` が、承認の要らない工程を**無条件で「完了」**にし、
契約に書いた「得意なこと」の1行目を実績として監査ログに書いていた。

処理は一切していない。**やっていないのに、やった記録だけが残っていた。**
承認後の処理も同じで、「承認済みの操作を実行しました」と書いていた。

`maturity: "実装済み"` が11体に付いていたのも、これと同じ問題の表側。

## 直したこと

### 1. 型で塞いだ

`StepStatus` に2つ足した。

- `NEEDS_INPUT`（入力待ち）— 入力が足りないので実行していない
- `NOT_IMPLEMENTED`（中身なし）— Agentの中身がまだ無い

監査ログの状態にも `未実行` を足した。成功でも失敗でもない。
やっていない、が正確な記録。**完了と同じ色にしない。**

### 2. 契約と実体を分けた

- 契約 = `lib/data/agents.ts`（何をしてよいか）
- 実体 = `lib/agents/registry.ts`（実際に処理するもの）

レジストリに無いAgentは動かない。動かないことを記録する。

`maturity: "動く"` を名乗れるのは、レジストリに実体があるものだけ。
**テストで固定してある**ので、表示だけ書き換えても通らない。

### 3. 入力が足りなければ止まる

Agentは `入力が足りない` を返して止まり、何が足りないかを項目名で言う。
推測で埋めない。埋めた瞬間に、それらしい嘘の出力が出る。

## 再発防止のテスト

- 実体の無いAgentが `COMPLETED` にならない
- 契約の「得意なこと」が、やった記録として書かれていない
- 成功と記録されているのは、実体が動いたものだけ
- 「動く」と書いてあるAgentには、必ず実体がある

## ついでに見つかった問題

`npm test` のグロブが `lib/**/*.test.ts` で、実際には `lib/*/*.test.ts`
までしか当たっていなかった。深い階層のテストが**静かに実行されていなかった**。
直した結果、27件 → 46件になった。

## 実行してみた結果

三河ハウスの案件を1件流すと、こうなる。

```
NOT_IMPLEMENTED  intake           受付 Agent はまだ中身がありません（契約のみ）。
NOT_IMPLEMENTED  document-reader  Document Reader はまだ中身がありません（契約のみ）。
NOT_IMPLEMENTED  validator        Validator はまだ中身がありません（契約のみ）。
WAITING_APPROVAL executor         金額変更にあたるため、承認を待っています。
```

以前はこの4つ全部が「完了」と表示されていた。
承認しても `PARTIAL_SUCCESS` で、成功にはならない。
