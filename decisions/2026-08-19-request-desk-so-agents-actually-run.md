## きっかけ

「これってさ他のエージェント使うよね?」
「あなたを通して依頼をすると、あなたが勝手に一人でやる仕様なんですね。
でしたらダッシュボードに依頼内容を書いて送信ってやった方が、
ちゃんとサブエージェントが稼働するのでは」

**そのとおりだった。** 遠州急行のデザイン案を作るとき、
役割分担Agentを1体も通さず、秘書が全部手でやっていた。
Agentを作った本人が、最初の実案件で使っていなかった。

## 何が起きていたか

秘書（Claude）に口頭で依頼が来ると、秘書はその場で作れてしまう。
Agentを通す理由が無いので、通さない。結果、

- ヒアリングで何が足りないかが分からないまま作り始める
- 工数も計測も公開前チェックも通らない
- 何を根拠にそう作ったのかが残らない

Agentを増やしても、通る口が無ければ動かない。

## 決めたこと

`/request`（依頼を出す）を作った。ここから出すと5体が順に動く。

    ヒアリング設計 → 情報設計 → 工数見積 → 公開前チェック → 計測設計

順番は `WEB_HANDOFF`（受け渡しの順番）から取る。
画面に順番を書き直すと、契約側とずれるため。

### 途中で止まっても、後ろも動かす

1体目で止めて聞きに行くと、打ち合わせが何回にも増える。
**足りないものをまとめて知りたい**ので、全部動かして未回答を集約する。

### 空欄のまま出してよい

分からない欄を埋めさせない。
**何が足りないかを返すのが、この画面の仕事**なので。

出すと「次の打ち合わせで聞くこと」が1枚にまとまる。

## 実際に遠州急行の件で通した結果

```
ヒアリング設計 Agent  → 完了
情報設計 Agent        → 入力が足りない
工数見積 Agent        → 入力が足りない
公開前チェック Agent  → 入力が足りない
計測設計 Agent        → 入力が足りない

次に聞くこと: 見る人 / ページ数 / 動きの程度 / 文章の担当 /
              チャットの有無 / 置き場所 / ドメイン / いまの件数
```

手で作っていたときは、この8件を聞かないまま作っていた。

## Agentが自分のバグを見つけた

情報設計Agentに通したら、こういう出力が出た。

```
ご依頼の流れ ｜ 連絡する
会社概要   ｜ （用途を確認する）
```

顧客がページ名を指定したとき、**並び順だけで用途を貼り付けていた**。
「ご依頼の流れ」に「連絡する」という、噛み合わない出力になる。

名前で照合し、当たらないものは「（用途を確認する）」と返すように直した。
推測で埋めると、それらしい嘘の構成ができる。テストで固定してある。

## 細かい直し

依頼フォームの上で「今あるサイト」のURLを書いてもらっているのに、
Agentが「今あるサイトはありますか」と聞き返していた。
一度言ったことを二度聞かない。URLがあれば作り直しとして扱う。
