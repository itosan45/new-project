## きっかけ

「ホームページとかデザインが絡むのは当然MCPでデザインサービスか
ワードプレス使うよね?」

そのとおり。ただ**「使えます」と書く前に実際に叩いて確かめた**ところ、
2つとも今のままでは使えなかった。

## 確かめた結果（2026-08-19）

| 道具 | 状態 | 中身 |
|---|---|---|
| コードで直接作る | 使える | Next.js / 素のHTML。このハーネス自体がこれ |
| Vercel | 使える | 公開先。実際に動いている |
| Googleドライブ | 使える | 画像・PDFから文字を読める |
| **Figma** | **権限が足りない** | 繋がっているが、席が「閲覧」。作成・編集ができない |
| **WordPress.com** | **権限が足りない** | 繋がっているが、機能が許可されていない |
| Canva | 認証がまだ | 認証していない |

Figma は `whoami` で確認。チームの席が View、プランは starter。
読むことはできるので、相手が作ったデザインをコードに起こすのは可能。
こちらから作るのはできない。

WordPress.com は機能を呼んだところ
「この機能はMCP設定で有効になっていません」と返ってきた。

## 有効にするために要ること（あなたの操作）

- Figma: 席を編集できるものに上げる（有料プランが要る）
- WordPress.com: wordpress.com/me/mcp で機能を有効にする
- Canva: claude.ai のコネクタ設定で認証する

## 決めたこと

`/can` に「使う道具」の節を足し、**状態と確認日**を出すことにした。

日付の無い「使えます」は、いつの話か分からず信用できない。
Agentの「いまの標準」に確認日を持たせたのと同じ考え方。

デザインが絡む仕事で取れる道を3つ並べ、それぞれの制約も書いた。

| 道 | 向いている場面 | 制約 |
|---|---|---|
| コードで直接作る | そのまま公開して、あとから直せる形で渡す | 相手が自分で更新するには向かない |
| WordPress.com | 相手が自分で記事を足したい | いまは機能が未許可 |
| デザインを先に起こす（Figma） | 見た目を先に合意したい大きめの案件 | いまは閲覧席。こちらから作れない |

## いま現実に取れる道は1つ

**コードで直接作って Vercel に出す。** これは実証済み。
残り2つは、あなたが権限を開ければ増える。
