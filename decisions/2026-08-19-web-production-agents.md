## きっかけ

「ホームページって言ったって、どこのサーバーに出すか、雛形なのか、
狙い、見るペルソナを何に誘導するのか、動画やJavaScriptのアニメーションは
入れるのか、SNSリンクやチャットボットがいるのか、公式LINEはあるのか。
色々設計構造はあるでしょ?」

そのとおりで、「ホームページ作れます」は答えになっていなかった。

## 決めたこと1: 18の決めごとを型にした

`lib/domain/web-project.ts` と `lib/data/web-decisions.ts`。

各項目は質問文だけでなく、次を持つ。

- なぜ聞くのか（相手に聞かれたときに答えられないと、ヒアリングが尋問になる）
- 決まらないまま進むと何が起きるか
- 見積を止める項目かどうか
- どの回で聞くか（1回で18項目は聞けない）

## 決めたこと2: 業種パックと職種Agentは別の軸

前に「専門性 = 共通Agent × ドメインパック」と決めたが、
これは**相手の業種**の話だった。Web制作は**うちの作業の役割分担**なので別の軸。

    建設会社のHP案件 = 職種Agent群 × 建設パック

両立する。混同すると、業種ごとにWeb制作Agentを作ることになる。

## 決めたこと3: 役割分担は8体。うち5体は実際に動く

| Agent | 中身 |
|---|---|
| ヒアリング設計 | **動く** — 未回答を聞く順に並べる |
| 情報設計 | **動く** — 狙いと導線からページ構成 |
| 見積根拠 | **動く** — 単価表から工数と内訳 |
| 計測設計 | **動く** — 何を数えるか。基準値が無ければ止まる |
| 公開前チェック | **動く** — 出してよいかの判定 |
| コピー | 契約だけ（文章は秘書が書く） |
| ビジュアル設計 | 契約だけ |
| 実装 | 契約だけ（コードは秘書が書く） |

判断が要る仕事をAgentの姿にするのは嘘になるので、契約だけのままにした。

## 決めたこと4: 「ベテラン」を飾りにしない

経歴文（"Web制作歴15年"）ではなく、次の4つをデータとして持たせた。

| 項目 | 中身 |
|---|---|
| 判断基準 | 「こういう時はこうする」と、その理由 |
| 地雷 | 経験者だけが知っている失敗 |
| 相場 | 見積の裏付けになる数字 |
| いまの標準 | トレンド。**必ず確認日つき** |

トレンドは黙って腐るので、`isStale()` で期限切れを検出して
画面に「要確認」と出す。

**参照されない経歴は飾り**なので、実際に出力へ効かせてある。
見積の単価は `lib/data/web-rates.ts` が唯一の出どころで、
契約に書いてある相場も同じ数字を見ている。ここを書き換えると見積が変わる。

数字はネットで裏取りしてから書いた（表示速度の基準、LINEの利用者数と開封率）。
裏取りできなかった項目は書いていない。

## 動かしてみた結果

何も決まっていない状態で見積を頼むと、こうなる。

```
入力が足りない
  作り方（buildStyle）/ ページ数（pages）/ 動きの程度（motion）
  / 文章の担当（content）/ チャットの有無（chat）
```

決まった状態だと、内訳つきで出る。

```
  3人日  土台（雛形を調整）
1.5人日  ページ追加 3ページ
  2人日  文章の作成 4ページ
  1人日  動き（軽く動かす）
  4人日  チャット（AIチャット）
  1人日  作り直しの引き継ぎ
合計 11.3〜17.5人日
```

金額は出さない。決めるのは人。
