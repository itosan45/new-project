# 2026-08-19

## 仕事の流れを6段階で設計した

仮想顧客の対応をいったん置いて、実際に仕事を受けるための土台を固めた。

    相談 → 提案 → 制作 → 納品 → 完了 → 運用

段階の切れ目は「相手の返事待ちになる場所」に置いた。
返事待ちが入るのは提案と納品の2つだけで、そこで止まっているのは正常な状態。

## 相談と提案は1回で終わらない

3回4回とまわる前提で型を作り直した。
打ち合わせは回ごとに記録し、その回で一番大事なのは「まだ分からないこと」。
これが次回の議題になり、空になったときに提案へ進む。

提案は版ごとに、もらった指摘を残す。残さずに版を重ねると同じ指摘を二度受ける。

## 提案設計 Agent を追加した（17体目）

「顧客の希望 → 各エージェントの意見・懸念 → 提案書」を組み立てる役。
誰が言った懸念かを残し、答えていない懸念があるうちは提案を出せないようにした。

金額の確定と懸念の削除は、この Agent の禁止事項に入れてある。
集約役が金額まで決められると誰も止められなくなるため。

## Agentに中身を入れ、嘘の「完了」をなくした

指摘のとおり、エンジンが何もしていない工程を「完了」にして、
契約に書いた文言を実績として記録していた。型と実装の両方で塞いだ。

- 工程の状態に「入力待ち」「中身なし」を追加。完了と同じ色にしない
- 契約と実体を分け、実体の無いAgentは動かない
- 「動く」と表示できるのは実体があるものだけ（テストで固定）
- 入力が足りなければ、推測で埋めずに止まる

Web制作の役割分担Agentを8体追加し、うち5体は実際に動く。
「ベテラン」は経歴文ではなく、判断基準・地雷・相場・いまの標準（確認日つき）
として持たせ、見積の計算が実際にその数字を参照する。

テストのグロブが浅く、深い階層のテストが実行されていなかったのも直した（27→46件）。

時間の見当は要るが、金額を決めるのは本人。
