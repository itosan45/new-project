# つながりの地図(グラフ)

「思いつき→決めたこと→実際の作業→できあがったもの」が、何を根拠に
つながっているかを自動でまとめて、見て確認できるようにする仕組み。

## 使い方

一番最初に1回だけ:

```bash
npm install
```

地図を作り直したいとき:

```bash
npm run graph
```

実行すると、以下の場所を全部読み込んで、`graph/graph.json` と
`graph/index.html` を新しく作り直す(古い内容は自動で上書きされる。
これは元のメモを消しているわけではなく、「今の状態からもう一度
地図を描き直している」だけ)。

- `notes/` `decisions/` `tasks/` `outputs/` `references/`
- `secretary/inbox/` `secretary/logs/`
- `departments/<部署名>/README.md` `departments/<部署名>/rules.md`
  `departments/<部署名>/notes/`

`graph/index.html` をブラウザで開くと、丸(ノード)と線(エッジ)で
つながりが見られる。丸にマウスを乗せると詳しい情報が出る。

## 丸(ノード)の色

- 青: note(思いつき)
- オレンジ: decision(決めたこと)
- 緑: task(作業)
- ピンク: output(できあがったもの)
- グレー: reference(根拠資料) / log(日々の記録)
- 濃い青: department(部署)

## 線(エッジ)の種類

線には3種類の「確からしさ」がある。

1. **フォルダの位置から分かる、確実な線**(実線)
   例: `departments/marketing/notes/2026-08-01.md` は
   `departments/marketing` に属する、など。人間が置いた場所からそのまま
   分かるので、間違いようがない。

2. **ファイルの中に自分で書いた、確実な線**(実線)
   各ファイルの先頭に、以下のように書いておくとつながりになる。

   ```markdown
   ---
   title: タイトル
   tags: [タグ1, タグ2]
   basedOn: [references/xxx.md]   # 根拠
   partOf: decisions/xxx.md        # 元になった決定/タスク
   supersedes: outputs/xxx-v1.md   # 作り直した場合、前のバージョン
   ---
   ```

3. **自動で「たぶん関係ありそう」と見つけた、推測の線**(点線)
   同じタグが2つ以上ついている、または文章の中に別のファイルの
   タイトルが出てくる、という単純なルールで見つけている。
   **これは本物のAIによる判断ではなく、簡単な自動チェックです。**
   間違って線が引かれることもあるので、話半分で見てください。
   (将来、ここを本物のAIによる判断に差し替えることもできる作りに
   してある)

## 中身を細かく確認したい場合

`npm test` で、この仕組み自体の動作確認ができる(自分でメモを書く分には
関係ない、開発者向けの確認)。
